# agents-md

一个用于**创建、增补和维护 `AGENTS.md`** 的 Agent Skill：先摸清项目事实，再套用一套可复用的政策基线，最后只补真实存在的信息，不发明技术栈、不编造命令。

基线措辞按原文保留，项目特有内容追加而非重写。删除或改写已有实质条款前必须得到用户确认。

## 安装

把整个目录放到任一 Agent 的 skills 目录下，目录名与 `SKILL.md` 里的 `name` 必须一致（本仓库为 `agents-md`）。

常见位置：

| Agent | 路径 |
| --- | --- |
| Claude Code | `~/.claude/skills/agents-md/` |
| 项目级（通用） | `<repo>/.claude/skills/agents-md/` |
| 其他支持 SKILL.md 的宿主 | 见宿主文档的 skills 目录 |

## 目录结构

```
agents-md/
├── SKILL.md                        # 主流程：定范围 → 找证据 → 提问 → 写入 → 校验
├── agents/openai.yaml              # 宿主 UI 展示配置
├── assets/
│   ├── AGENTS.template.zh-CN.md    # 中文基线模板
│   └── AGENTS.template.en.md       # 英文基线模板
└── references/
    ├── discovery.md                # 怎么摸项目事实、证据表怎么记
    ├── interview.md                # 首次建立时该问什么、怎么问
    ├── writing.md                  # 怎么写、怎么打补丁、怎么保留原文
    └── ux-delivery.md              # 界面与交付附加条款（前端/小程序/App/H5）
```

## 工作流程（SKILL.md 五步）

1. **定范围**：确认目标目录与仓库边界，读已有的 `AGENTS.md`、`CLAUDE.md`、`AGENTS.override.md`，判断是新建、增补还是只审计（审计只出结论、不落盘）。
2. **找证据**：读文档、清单、脚本、CI 与代表性源码，维护一张「候选条款 → 证据 → 状态 → 下一步」的证据表。已验证的直接写，推断的需核对，冲突的必须问。
3. **只问证据答不了的**：首次建立时一次性问清语言、基线例外、验证方式等；缺失信息不影响正确性就不问。
4. **写入或打补丁**：新建则原样复制基线模板再填占位符；已有文件则以现有内容为底，补缺失条款，保留用户原文与自定义章节。
5. **校验与交付**：逐条核对事实有据、路径存在、基线条款未被擅自改写、被删条款都有确认；交付时说明实际做了哪些检查。

## 基线模板包含什么

中英两份模板内容对称，均为：项目入口（目标/架构/约束/文档/特殊路径/长期记录 + 命令表）、工作原则、安全边界、验证与评审（含变更分级检查表）、交付与维护。

其中工作原则里的这条是**基线必备**，新建和增补都要有：

> 控制上下文与输出成本：先定位再读取，只读与当前任务相关的代码片段，不通读无关文件或整仓；保留命令输出与日志时只截关键行或写摘要，不复制冗长原始内容；同一读取结果任务内复用并按需压缩。

## 界面驱动项目的附加条款（`references/ux-delivery.md`）

前端、小程序、App、H5 这类以界面质感为核心的项目，或用户要求把界面与交付规范固化时，把该文件的条款**原样**作为一个独立章节插进 `AGENTS.md`，建议标题 `界面与交付（本项目附加）`，位置放在基线「工作原则」之后。它是追加政策，与基线冲突时以本节为准。

该文件目前覆盖：工作原则（少而准的截图验收）、界面设计原则（去冗余文案、自解释布局）、具体开发要求（tooltip 替代常驻说明、危险操作后果提示、可访问性）、交付收尾规范（验收点核对 → 交付物清单 → 坑点归档）。

## 坑点双层机制（通用 vs 私有）

这是本 skill 里最需要理解的设计，目的是让「可复用的执行坑」沉淀到模板，让「一次性业务坑」不外溢。

| 层 | 位置 | 生效范围 | 谁来写 |
| --- | --- | --- | --- |
| 通用高频 Gotchas | `references/ux-delivery.md` 的「通用高频 Gotchas（新项目自动继承）」章节，生成时原样导入每个新项目的 `AGENTS.md` | 所有新项目 | 仅在确认「跨项目会复现」时更新 |
| 本项目私有 Gotchas | 生成的 `AGENTS.md` 里的「本项目私有 Gotchas（仅本项目生效）」章节，初始为空占位 | 仅当前项目 | 会话收尾时把本项目独有的坑追加进去 |

规则要点：

- 生成新项目 `AGENTS.md` 时，**禁止**把旧项目「本项目私有 Gotchas」里的任何条目带过去。
- 每条坑统一写法三项：【现象】【触发条件】【规避做法】。规避做法必须可执行，禁止模糊描述。
- 业务特有、单次偶然的环境问题**不得**写进通用区，否则会污染所有后续项目。

## 自定义

- 想改所有新项目的默认政策：直接改 `assets/AGENTS.template.*.md`，两份语言版本保持对称。
- 想改界面/交付类政策或通用坑：改 `references/ux-delivery.md`。
- 想改流程本身（问什么、校验什么）：改 `SKILL.md` 与对应 reference，注意同步第五节校验清单。
